# 种子格式化工作台

选择一个下载器中的种子，核对媒体信息和本次规则，通过目录树/差异清单预览后明确确认执行。手动工作台不依赖事件或定时任务开关。

## 使用流程

1. **选择种子**：列出所有已启用、受支持的下载器，可按名称或 Hash 搜索。点击轻量卡片只选中并读取详情，停留在当前页；浅色背景和边框标识唯一目标，不显示圆形单选标记。核对摘要中的名称、下载器与保存路径后，点击「下一步：媒体信息」继续，桌面按钮固定在右侧摘要区底部，手机与分页范围按钮共用一条固定底栏。未选择、详情读取中或失败时不能推进，失败可重试。搜索、分页保留目标，重复点击当前种子不清空编辑；选择另一条或切换下载器才重置媒体与临时规则，不会累计多选。选择页不提供提前生成预览或执行入口，已有处理记录仍需先恢复。
2. **媒体信息**：使用 MP 下载记录、辅种源记录或宿主名称识别；手动输入区在「搜索媒体」与「指定 TMDB ID」之间二选一，默认搜索。切换方式不改变上方「当前生效媒体」，只有选择结果或点击「应用此 ID」才应用新的身份。没有 MP 记录也能手动指定。
3. **本次规则**：临时覆盖四个模板和两个开关，不影响已保存配置。空保存路径模板表示不移动，关闭开关或清空模板都按本次输入生效。
4. **变更预览**：宽内容区并列显示目录树，窄屏切换前/后布局；可展开目录、搜索路径、筛选相关项、点击文件核对完整位置，或按状态查看分页差异。
5. **确认执行**：确认窗再次列出下载器、Hash、媒体与目标，勾选核对后才能提交。后台在第一次修改前保存原状态，逐项回读结果。
6. **处理历史**：按名称、Hash、原/转种目标下载器或路径搜索，可分别筛选「种子状态」和「处理结果」。先预览恢复、确认完整恢复，再按新规则处理；也可跨页累计选择后一次删除插件备份记录。

插件容器宽度小于 720 px 时，所有工作台页面和配置页三个分组统一使用 `.tf-layout` 作为主滚动区：分组导航、编号、标题、说明及普通内容一起滚动。外层品牌与切换、刷新、关闭操作栏在滚动区外固定占位，不随内容滚走、不覆盖内容；底部主要操作和配置保存同样位于滚动区外，短视口仍可达。工作台手机底栏只有一行：选择页显示「当前范围 / 总数 ▾」与「下一步」，媒体和规则页显示「上一步 / 生成预览 / 下一步」，预览页显示「上一步」与确认或重新生成操作。断点按插件壳宽度而非浏览器宽度判断，跨手机/桌面断点不重新挂载输入表单。桌面和平板将流程操作固定在右侧摘要区底部，摘要本身可以滚动；种子列表独立滚动，完整分页留在内容区底部。

手机种子分页固定每页 **20 个**，不提供数量设置。点击底栏范围按钮（如 `41–60 / 355 个种子 ▴`），像下拉选择框一样在按钮上方向上展开页码菜单。菜单从上到下按页码倒序排列，使用 `03 / 41–60` 这样的两位编号与范围分列展示，不显示「第 xx 页」或「个种子」。当前页使用主题色、浅色背景和右侧勾号；每行约 40 px，菜单宽 180 px、最多展示约 6 行，打开时确保当前页可见。选择页码立即跳转，不需要填写表单或点击应用。菜单高度受限，可滚动到任意页；Escape 或点外部关闭不改变分页。无结果时底栏显示 `0–0 / 0 个种子`。分页保留已选种子及该目标的媒体、规则和预览，关闭菜单后焦点返回范围按钮。桌面仍支持修改每页数量；跨入手机布局时换算为每页 20 个的对应页码，尽量保留原来可见范围的起点。

历史当前页会核验原位置与已知连续转种链，每个下载器仅获取一次种子摘要，不读取所有文件。普通浏览可复用最多 5 秒的下载器摘要，卡片显示真实核验时间及「5 秒缓存/实时查询」；手动刷新使用 `fresh=true`，删除、恢复和按 ID 核验始终实时检查。优先最终转种目标；只有确认目标缺失才回退之前位置。离线/查询失败标为「下载器不可用」，不能判定种子已删除。Transmission 数字 ID 不作为实际身份，查找仍使用备份 Hash。

历史页的初始顺序与其他页面一致：分组导航后是编号、标题和说明，其下依次为完整删除风险警告、搜索筛选行、批量工具栏和历史记录。手机历史 panel/records 为正常流内容，随 Shell 的 `.tf-layout` 统一滚动；桌面仍由 records 独立滚动。手机导航、标题和警告向上滚走后，筛选与批量工具栏到达内容区顶边时才一起吸顶。匹配总数、页码和翻页按钮始终固定在底部：同一份分页模板在手机通过 Teleport 迁移到壳直属的 `.tf-pagination-host`（不在 dock 内），桌面留在 panel 内；首次挂载和跨断点切换不复制控件、不丢失页码和选择。查询/选择错误随记录滚动。吸顶时仅用 150ms 轻微阴影过渡，不改变控件高度或位置；减少动态效果设置下禁用过渡。刷新入口留在筛选行，加载进度细线不挤占记录高度。

桌面和平板将「搜索历史 / 种子状态 / 处理结果」放在同一行；手机保留搜索框与筛选按钮，两个状态下拉仅在「历史筛选」底部弹层中显示。按钮的无障碍名称「筛选历史（N 项状态筛选）」只统计两个状态筛选，不计搜索关键词；选择立即更新结果，「清除筛选」同时清空关键词和状态，「完成」或 Escape 关闭弹层后焦点返回筛选按钮。暗色和透明主题的弹层保留不透明卡片背景，避免透出记录影响阅读。

手机批量工具栏保持单行，显示本页选择、`N/100`、按需实时核验和删除；简短显示不改变「删除所选记录」「实时核验所选」的无障碍名称、禁用条件和确认保护。桌面、平板和手机均可在滚动时继续跨页选择与翻页，且不产生横向页面滚动；右侧核验摘要只在宽屏展示。

「删除记录」只清理选中插件备份、日志及其状态，**不删除下载任务或文件，也不会还原已修改目录**。勾选按稳定历史 ID 跨页保存，「本页全选」只切换当前页可删除项；搜索、筛选或插件实例变化会清空选择。每次最多提交 100 个不同 ID，单条操作也使用长度为 1 的同一批次接口，不循环旧接口。确认窗展示冻结的完整清单和数量，并要求再次确认放弃恢复能力。

批次内删除、已不存在、签名冲突、忙碌及失败会逐项展示；仅明确 `deleted/not_found` 的记录从当前列表局部移除并去重减少总数，其他项及原因保留，不自动重试。当前页还有记录时不会刷新历史、种子或详情；删空且仍有匹配记录时只补查一次，必要时回退末页。关联种子、详情和恢复预览只标记过期，进入相关页面或再次操作前才按需刷新，不会直接把 `processed` 改成 false。其他下载器的同 Hash 记录不受影响。

请求超时或提交后响应丢失不会冒充成功或失败，也不会自动重发。所选快照保留为「结果未知」，用户只能显式调用只读 `history_lookup` 核验；仅明确 `not_found` 才移除。仍存在、后来重建或签名变化的记录必须重新查看完整清单并再次确认。

「保存目录移动」与「相对文件改名」分别计数；全路径受影响的文件数是布局范围，不等同于已传输的字节数。执行后右侧目录树使用下载器实际回读，不能把未执行的计划目标当作成功。

## 支持与保护

| 能力 | qBittorrent | Transmission |
| --- | --- | --- |
| 保存位置修改 | 支持 | 支持 |
| 独立显示名 | 支持 | 不支持，预览明确标注 |
| 文件相对路径 | 支持 | 仅同目录 basename 改名，不支持任意跨目录重排 |
| 自动管理 | 移动前按需关闭，恢复时还原 | 不支持 |

- 接口使用 bearer 鉴权；与宿主插件配置保持一致，只有激活的超级管理员可以读取规则、预览临时 Jinja2 模板和执行源目录操作。
- 媒体优先级：本次指定 → 下载历史/辅种源关联 → 宿主识别；事件处理复用其已有元数据。
- 电视剧可以补充缺失季号（0 为特别篇）；不能确定的集数会跳过，**不会按文件排序猜集数**。
- 手动处理仍遵守排除目录、标签和系统整理屏蔽词。目录按边界匹配，标签按精确值匹配。
- 模板目标禁止空值、绝对路径、`..` 越界、保留名、过长路径及文件冲突。不会覆盖/交换其他文件。
- 预览 token 默认有效 **10 分钟**，每实例最多 **50** 个；切换输入、后端状态/配置变化、插件重载或过期都要求重新预览。
- 新记录按「下载器 + Hash」隔离。旧 `processed` / `pending` / Hash 备份兼容只读；归属冲突不猜测，缺失/不一致的备份不会自动删除。
- 恢复校验稳定文件 ID、数量与大小。旧备份仅在可验证顺序时回退匹配；转种目标按备份 Hash 核验，不会操作被重用数字 ID 指向的其他种子。
- 下载/文件记录只更新当前下载器的字段，使用事务内条件更新防止覆盖并发改动；宿主挂载根仅按已知文件对应关系投影。未知存储 URI 保留，辅种源历史只用于识别。

## 风险与结果状态

这是**源下载目录操作**，不是媒体库副本整理。改目录/文件名可能影响辅种和整理记录关联；文件改名保留为实验功能。

部分异常也保留原备份和操作日志。异步移动、超时或回读不确定时显示「确认中/部分执行」，不能简单提示完成。结果回查只核实已提交的操作并同步已确认路径，**不重发移动/改名，也不继续未执行项**。不承诺跨下载器与数据库的原子回滚。

纯显示名修改也能恢复；只有完整布局和下载记录都确认恢复后才清理历史。插件重置会清除备份，请不要用重置代替恢复。
